clog CLI
bin/clog · lib/config.sh · lib/jsonl.sh · HEAD 96ae789

clog schema 1.0

Append one JSON line per event to a daily JSONL log. This page documents the command-line surface the way Swagger UI documents an HTTP API: one operation per entry type, shared parameters, responses as exit codes, and the entry, config and environment as schemas.

The CLI is not an HTTP API. The "operations" and "responses" below are shell invocations and exit codes; there is no OpenAPI document. clog serve starts a separate local HTTP API that wraps the CLI, documented in HTTP API. Every CLI behaviour on this page was read in bin/clog and lib/ or run against a scratch log root at the commit in the top bar; the spec it is pinned to is openspec/specs/, exercised by tests/cli/run.sh.

Synopsis

clog <TYPE> "<summary>" [--agent NAME] [--repo NAME] [--session ID] [--model NAME]
     [--file PATH] [--family FAMILY] [--kpi KPI] [--date YYYY-MM-DD] [--time HH:MM:SS] [--echo]
clog serve [--port N]        # start the local HTTP API (default 127.0.0.1:4848)
clog --help | clog -h        # first argument only

Flags must follow the two positionals. Nothing is printed on success unless --echo is given. The entry is appended to <log_root>/<log_subdir>/YYYYMMDD.jsonl, creating the directory and file on demand.

Operations one per TYPE · case-sensitive · any other value exits 1

ACTIONclog ACTION "<summary>"Non-code state change▶

Agent dispatched, tool called, file moved, API call made, config changed, setup completed. If it produced an artifact or changed external state and did not resolve a tradeoff, it is an ACTION.

Example

clog ACTION "dispatch orchestrator for phase 2 planning" --repo my-repo --agent orchestrator

Entry

{"time":"09:15:22","type":"ACTION","summary":"dispatch orchestrator for phase 2 planning","agent":"orchestrator","repo":"my-repo","session":"sess-abc123"}

Also written automatically by hooks/post-action-log.sh on git push (pushed <branch> (<repo>)) and by hooks/pre-agent-clog.sh on every Agent dispatch that carries a description.

DECISIONclog DECISION "<summary>"A tradeoff resolved▶

Choice between approaches, naming, architecture, scope. Include the option chosen and why.

Example

clog DECISION "use yq with grep/sed fallback — avoids mandatory dep"
{"time":"09:32:44","type":"DECISION","summary":"use yq with grep/sed fallback — avoids mandatory dep","repo":"my-repo"}
CODEclog CODE "<summary>" [--file PATH]A file edited or created▶

New function, bug fix, refactor, test added. Use --file for the path the entry concerns.

Example

clog CODE "add session fallback chain in bin/clog" --file bin/clog
{"time":"10:01:05","type":"CODE","summary":"add session fallback chain in bin/clog","repo":"clog","file":"bin/clog"}

Also written automatically by hooks/post-write-clog.sh as auto: wrote <absolute path> on every Write, Edit, MultiEdit or NotebookEdit.

PRclog PR "<summary>"Pull request opened, updated or merged▶ 
clog PR "Created PR: add clog skill — main https://github.com/org/repo/pull/123"

Also written automatically by hooks/post-action-log.sh on gh pr create, with the --title value as the summary.

COMMITclog COMMIT "<summary>"A git commit landed▶

Normally written by hooks/post-action-log.sh on git commit, using the first -m message of the command as the summary (one entry per Bash command, however many commits it makes). The hook adds a commit field (short SHA) to that entry when it can resolve the repo (git -C, leading cd, the hook's working directory, then $HOME); the CLI itself has no --commit flag.

{"time":"11:46:33","type":"COMMIT","summary":"feat(hooks): add post-log-reminder","repo":"clog","commit":"a3f9b12"}
REPOclog REPO "<summary>"Repo-level event▶

git init, clone, archive.

clog REPO "git init ~/Code/clog — new public clog package"
FOLLOWUPclog FOLLOWUP "<summary>"Something to revisit▶

Discovered anomaly, deferred decision, open question, known debt.

clog FOLLOWUP "investigate whether Cursor exposes hooks API"
LEARNINGclog LEARNING "<summary>" --family F --kpi KAgent meta-feedback▶

A finding that changes how the agent should behave next time: prompt gap, pattern, correction to a prior claim. Reserved for agent meta-feedback. The retro skills only see entries that carry --kpi.

A value outside the configured list is still written; the entry gains "validation":"unknown_family", "unknown_kpi" or "unknown_family,unknown_kpi". Nothing is printed. When the config declares no list, no validation happens.

clog LEARNING "rapid-fire edit chain — checkpoint deferred at each pause" --family interactive --kpi failure
{"time":"15:00:00","type":"LEARNING","summary":"rapid-fire edit chain — checkpoint deferred at each pause","family":"interactive","kpi":"failure"}
LESSONclog LESSON "<summary>"A concept the user learned▶

Deliberate study or practice: idiom understood, pattern recognised, doc that clicked. Never collapse with LEARNING, which is about the agent.

clog LESSON "Go interfaces are structural, not nominal — like TS interface without implements"
serveclog serve [--port N]Start the local HTTP API▶

Runs a Hono server on 127.0.0.1 (default port 4848; --port 0 picks a free port) until SIGINT or SIGTERM, then exits 0. It prints two lines to stdout: clog API listening on http://127.0.0.1:<port> then clog API token: <token>. The token is 32 random hex characters per launch, or the value of CLOG_API_TOKEN when that is set and non-empty; send it as Authorization: Bearer <token>. clog serve --help prints a one-line usage and exits 0. Every write spawns bin/clog --echo, so the CLI stays the single source of truth. Build first with npm install && npm run build.

HTTP API clog serve · 127.0.0.1 only · bearer token · try it at /demo

Routes are relative to the router mount; standalone, the mount is /. Request and response bodies are JSON. Every error is { "error": { "code", "message" } }; where bin/clog rejected the entry, message is its first stderr line verbatim. No error body carries a stack trace. Any route can also answer 500 internal_error with the message internal server error for an unexpected failure (the detail goes to the server's stderr only).

POST /entries

Body: { "type", "summary", "agent"?, "repo"?, "session"?, "model"?, "file"?, "family"?, "kpi"?, "date"?, "tags"? }, all strings except tags, a non-empty array of non-empty strings without commas (passed as --tags, so the entry's tags is the server's default tags followed by these, trimmed and deduplicated). type and summary are checked before spawning with the CLI's own messages, and the shape of tags (no commas or control characters in items) with the server's; everything else (date, family, kpi) is passed through and the CLI's verdict is mapped. A field containing a NUL character is refused with 400 invalid_field before anything is spawned. Writes are serialised: the server runs one bin/clog at a time, so concurrent POSTs queue and never interleave in the day file. If the CLI printed the entry and then exited non-zero (for example the auto-commit step failed), the entry is on disk and the answer is 201 with warning set to the first stderr line. An unknown family or kpi is still a 201 with entry.validation set. repo defaults to the git repo containing the server's working directory, or is absent when there is none; session is absent unless supplied (the server strips the session environment variables from the child). With CLOG_DISABLE=1 in the server's environment the answer is 503 disabled and nothing is written, whether or not a config file exists (the CLI honours the switch before it looks for a config, and so does the API on all three guarded routes).

POST /entries
{"type":"ACTION","summary":"deploy to staging","repo":"my-repo"}

201
{"entry":{"time":"09:15:22","type":"ACTION","summary":"deploy to staging","repo":"my-repo"},"file":"/Users/me/clog-logs/claude/20261021.jsonl"}

GET /entries

Query: date=YYYY-MM-DD (default today, local time; empty means today), type, repo, session, agent (exact match), tag (the entry's tags contains it; empty is 400 invalid_tag), all ANDed, tail=N (1 to 10000, applied after filtering). A missing day is entries: []; a line that is not valid JSON is skipped and counted in skipped.

Bearer token

GET /config, GET /entries and POST /entries require Authorization: Bearer <token> and answer 401 unauthorized (missing or invalid bearer token) without it. /health, /demo, /docs and CORS preflights need no token. A mounted createClogRouter({ token }) enforces the same check; without token the router is open.

Origins and limits

CORS allows only origins matching ^http://(localhost|127\.0\.0\.1)(:\d+)?$ (GET, POST, OPTIONS; Content-Type, Authorization); any other origin, including null from a file:// page, gets no allow header. Request bodies over 64 KiB are refused with 413. POST /entries requires Content-Type: application/json (else 415 unsupported_media_type). A Host header other than 127.0.0.1 or localhost (optional port) is refused with 403 forbidden_host (DNS-rebinding guard; the bare router leaves this to the mounting app). The router is exported as createClogRouter so another Hono app can mount it under a prefix. createClogRouter({ spawnTimeoutMs }) sets how long a write may run before it is killed and answered 500 clog_timeout (default 10000); the CLI's whole process group is killed (SIGTERM, then SIGKILL), so a hung git or jq cannot hold the response.

Config — ~/.config/clog/config.yaml (or $CLOG_CONFIG)

Parsed with yq v4 when on PATH, else a grep/awk fallback. Both parsers agree on the shapes used in config.yaml.example (flat key: value, the nested auto_commit: block, block lists of - item). The fallback does not strip inline # comments from values and does not read inline lists (families: [a, b] yields an empty list). Values may start with ~ or ${HOME}.
